## 项目一句话定位

**SomaOS Brain Next (SomaOS 运动执行脑)** 是一个面向实体机械
臂的**零依赖安全执行内核**。它对标高等动物的**"脑干 (基本生存
反射) + 小脑 (快速时序协调)"**组合, 在极其受限的硬件资源
条件下, 依然为 Feetech SO-100 六轴机械臂提供**工业功能安
全级别的双层动作筛选 + 确定性实时执行 + VLA 热插拔接入**。

设计哲学一句话: **确定性运行时 + 双重安全门控 + 轻量化哲学**。
本脑承担"脑干+小脑"角色——接收 RCAN 标准指令或外部 VLA 预
测, 经双层动作筛选后立即下发至实时执行层, 以最小资源占用
保证动作的安全可验证。

- **适用硬件**: Feetech SO-100 六轴机械臂 (Feetech 总线舵机系列)
- **推荐算力**: 树莓派 4+ / Jetson Nano+ / Jetson Orin (低至 1GB
  内存 + 4 核 ARM 级别即可稳定运行)
- **操作系统**: Linux (Ubuntu 22.04+ 推荐); Windows 开发可用
- **对外接口**: 标准化 RCAN 指令入口 / HTTP 本地控制接口 /
  可选 VLA 上游模型接入 / ESTOP 急停总线输入 / 状态事件回流输出

## 为什么 SomaOS Brain Next 不只是"又一个机械臂控制器"

2026 年具身智能的主流运动执行路径有两种极端:

1. **重软件栈派**: 跑完整 ROS 2 + MoveIt 2 + 多种插件栈。功
   能非常全, 但代价是——**几百万行代码的依赖闭包**、启动几
   十分钟、任何一个库更新都可能引入安全回归、最终只能在
   x86+GPU 机器上跑。
2. **极简固件派**: 把控制逻辑写进 MCU 固件/裸板循环。资源
   占用极低, 但代价是——**所有安全规则都硬编码在无法热更
   的固件里**, 对接 VLA、接入认知上游、记录经验回放都成了
   不可能任务。

SomaOS Brain Next 刻意选择了**中间第三态**——它比固件派的
功能强大两个数量级 (可接 VLA、有经验回放、有标准化指令入
口), 同时比 ROS 2 派的依赖闭包小了几个数量级 (0 个外部
npm 包)。这种**软件栈重量与运行时能力之间的非对称取舍**
是 Brain Next 最核心的设计主张。下表是具体的 6 项差异化
特征:

| 主流执行方案的结构性痛点 | SomaOS Brain Next 的设计对策 |
|---|---|
| 依赖爆炸: 完整 ROS2/MoveIt2 依赖闭包百万行, 安全审计不可能 | **零依赖可验证运行时内核** (§1: dependencies = {}) |
| 安全是外挂: Action Shield / CBF 在决策链外部, 与执行器不同步 | **双重动作筛选确定性执行安全模型** (§2: 慢路+快路 同核内生) |
| VLA 绑定: 换一套 VLA 就要跟着重做一整套安全验证 | **VLA 热插拔上游接入契约** (§3: 换模型 = 改一行 URL) |
| 经验回放是滚动窗口 FIFO: 宝贵的失败样本被"成功样本"淹没 | **高价值失败信号优先经验回放** (§4) |
| 运行时状态不可观测: 执行崩溃了不知道是哪一层触发的 | **全链路可追溯事件总线 + 结构诊断快照** (§5) |
| 资源浪费: 跑个舵机控制也要塞 Orin, 算力全花在了调度上 | **1GB RAM / 4 核 ARM 级资源天花板约束** (§6) |

### §1 零依赖可验证运行时内核 (Zero-Dependency Verifiable Runtime Kernel)

**要解决的核心痛点**: 在嵌入式/机器人场景中, 供应链攻击与
第三方库的隐式副作用是两大未被严肃对待的安全漏洞来源。
一个典型的机器人软件栈可能有几千个传递性依赖包——任何一
个包的最小版本升级都可能在运行时引入不可预测的异步行为。
当执行链涉及真实物理扭矩时, 这种不可预测性就是人身与设备
安全的直接风险。

**SomaOS 的设计思路**: Brain Next 的执行内核**声明运行期零
外部依赖** (package.json dependencies = {})，仅使用标准运行
时的内置模块。这为内核带来三个关键属性:

1. **可移植性 (Portability)**: 任何支持标准运行时的设备 (从
   树莓派、Jetson 到云端容器) 都能运行, 不依赖包管理网络,
   离线部署与长期维护成本极低。
2. **可审计性 (Auditability)**: 传递性依赖攻击面归零。内核
   代码可以在数小时内由安全工程师完整审计完成, 不必逐个
   检查几千个第三方包的行为。这一点对于任何想要通过工业
   级安全认证的项目是**前置条件**。
3. **可确定性 (Determinism)**: 没有来自第三方库的隐式异步
   事件、没有网络拉取配置、没有意外的 console 与日志线程,
   执行时序的可预测性显著提升。对于毫秒级的运动控制而言,
   这是一个"有没有"级别的基础能力。

零依赖设计的真正价值, 不在于"省几个 npm install 命令",
而在于它让内核的执行安全变成了**可形式化分析**的命题, 而
不是靠运气的经验测试。这是 Brain Next 区别于全栈派控制器
的**第一根本差异**。

### §2 双重动作筛选确定性执行安全模型
### (Dual-Layer Action Filter with Deterministic Execution)

**要解决的核心痛点**: 在工业功能安全领域, "单一安全规则"
早已被证明是不够的——最危险的事故往往发生在安全规则本身
失效的瞬间 (例如安全门控的超时回调被调度器阻塞、安全规则
与决策规则共同引用同一个被污染的全局状态, 等等)。单一安
全结构的系统, 当安全结构自己出 bug 时就完全裸体了。

**SomaOS 的设计思路**: 借鉴工业功能安全中 **"Intentional
Gating (意图级防护) + Reflex Protection (反射级防护)"** 的
双层防护模式, 构建了一个慢路 + 快路的双通道执行安全模型。
两条路径在代码、调用、数据流三方面物理独立:

1. **路径一 (慢路 · 意图级动作筛选)**: 动作进入队列之前,
   四项独立规则并行判定——
   - 置信度评分过滤 (置信度不足的低确定性动作不进入执行)
   - 动作语义合法性分类 (拒绝语义上超出当前能力声明的动作)
   - 冷却执行限制 (防止极高频率指令刷爆舵机)
   - 并行合法性否决 (多来源、独立视图、一票否决)
   这一路延迟目标在毫秒级, 与一般的调度周期相当。

2. **路径二 (快路 · 反射级急停)**: **几乎不经过任何代码路
   径分支**。在执行器入口的最末端直接提供一条等效于硬件级
   扭矩释放的直通路径。当 ESTOP 总线触发、或快路内部的简
   单状态机进入急停模式时:
   - 运动队列立即清空
   - 急停事件在事件总线上广播
   - 执行器扭矩立即释放
   三件事近于同步完成, 并且**完全不依赖慢路的任何代码路径或
   状态**——慢路死锁、慢路内存泄漏、慢路回调阻塞、慢路任何
   形式的失效, 都绝对不会影响快路的急停生效。

两条路径的**独立性设计**使得安全模型可以被**形式化分析**
(独立于经验性的黑盒测试)。当你能从代码结构上证明"路径 A
与路径 B 无共享调用、无共享数据", 那么你对安全的信心就不
再来自于"我们测过了, 没出问题"——而是来自于结构本身的不
可互扰性。这是 Brain Next 区别于外挂安全层的**第二根本差
异**。

### §3 VLA 热插拔上游接入契约
### (VLA-Pluggable Upstream Inference Contract)

**要解决的核心痛点**: 2026 年具身智能正处在 VLA 模型快速迭
代的爆发期。今天最先进的 VLA, 半年后就会被新的架构、新的
训练数据、新的模型尺寸超越。如果一台机器人的安全行为与
"当前使用的是哪个 VLA"紧密耦合——那么, 每换一次上游 VLA
模型, 机器人整套安全行为就要从头验证一遍。这个验证成本会
让用户永远停留在某一个 VLA 版本上, 浪费整个行业的进步。

**SomaOS 的设计思路**: Brain Next 执行内核本身**不承担视觉-
动作大模型推理**。它只预测确定性执行与安全筛选; VLA 推理
由上游模型 (可以是任何云端/本地/异构供应商的 VLA) 完成。
两者之间用一个**语义标准化的上游接口契约**对接:

- 上游 VLA 提交的动作预测, 始终落在同一语义契约上 (动作
  形状、单位、夹爪语义命名全局一致)。
- **安全内核始终保持行为不变性**: 上游模型的任何预测, 都
  必须通过 §2 的双层动作筛选才能真正下发到执行器。内核的
  慢路规则、快路急停、冷却限制、与上游模型版本完全正交
  —— 换 VLA, 不换安全。

这种设计带来一个极其重要的工程结论: **"换 VLA ≠ 重做安全
验证"**——只要新旧 VLA 遵守同一契约, 安全行为就不需要重
新验证, 工程师只需要验证 VLA 的任务成功率, 而不必担心它
会打破机器人的安全边界。这使得用户能够以极低成本拥抱
VLA 技术的快速演进。这是 Brain Next 区别于"VLA 与控制器
深度绑定"架构的**第三根本差异**。

### §4 高价值失败信号优先经验回放
### (High-Value Failure-First Experience Replay)

**要解决的核心痛点**: 大多数执行系统做经验回放时, 用的是简
单的**滚动窗口 FIFO 队列** (最近 N 条经验全保留)。这种做
法在数学上的缺陷是: 机器人 99% 的动作都是成功的, 成功样
本会迅速填满缓冲区; 而真正能告诉 VLA "在哪里、为什么做错
了"的失败样本, 在滚存中被 1% 的比例稀释到几乎看不见。昂贵
的真机采集数据就这样被浪费掉了。

**SomaOS 的设计思路**: Brain Next 的经验存储中内置了一套
**高价值失败追踪器**。每次执行失败后, 失败样本会被送入
结构分类器打上三类标签之一:

1. **自信错判型失败 (Overconfident Error)**: 上游 VLA 给
   出高置信度但实际失败——对应"VLA 需要特别关注的盲区"。
2. **新场景首次失败 (Novel-Scenario First Failure)**: 语义
   嵌入距离历史经验都足够远的新分布样本首次失败——对应
   "VLA 的分布覆盖边界缺口"。
3. **安全门控误拦 / 漏拦 (Gate Misjudgment)**: 慢路或快路
   的筛选判断与真实安全需求不一致——对应"门控本身需要调
   节的证据"。

非这三类的普通失败样本与成功样本按常规比例留存。在对接
后续 VLA 微调时, 高价值失败样本自动获得**过采样优先权**
(加权重放), 比普通滚动回放更高效、更有针对性地修补模型
短板; 同时对**单样本过采样次数设置严格上限**, 防止单条
失败样本过度污染导致模型过拟合。

这使得有限的真机采集小时数, 在 VLA 微调中的**数据利用效
率显著优于滚动窗口方案**。

---

### §5 全链路可追溯事件总线 + 结构诊断快照
### (Full-Chain Traceable Event Bus with Diagnostic Snapshots)

**要解决的核心痛点**: 执行系统崩溃或出现意外行为时, 调试
的最大敌人是"不可观测性"。如果急停触发了, 但没人知道是
"慢路哪一条规则否决了动作"还是"快路收到了 ESTOP 总线输入
还是内部判定急停"——那么下一次重现事故就是运气游戏, 根
本无法根因定位。

**SomaOS 的设计思路**: Brain Next 的内核内部所有关键决策
点 (慢路四规则的通过/否决、快路急停触发来源、队列入列出
列、后端状态变更、VLA 上游预测到达与被接纳情况) **全部以
结构化事件形式写入统一事件总线**, 每个事件带时间戳、触
发源、结构上下文快照。事件总线对外暴露标准化订阅接口,
因此:

- 外部诊断工具可以实时接入观察执行状态, 不需要修改内核;
- 状态快照可落盘用于 VLA 训练数据集制作 (失败信号 + 上下文
  快照就是 §4 的高价值失败样本)。

当用户报告"某条指令下机器人误动了", 第一件事不是猜, 而
是把事件总线快照拉出来, 慢路四条规则分别给出的判定、上
游 VLA 的预测、快路状态一眼可见。这就是可追溯。

---

### §6 1GB RAM / 4 核 ARM 级资源天花板约束
### (1GB / 4-core ARM Ceiling Constraint)

**要解决的核心痛点**: 绝大多数具身智能项目的 demo 视频都
是在 x86 + GPU 机器上跑出来的。演示看起来很惊艳, 但当用户
真的想把这套系统装进实体机器人——他会发现, 光是推理依赖
就得吃掉 Orin 的内存, 运动控制只能和推理抢资源; 如果他想
在树莓派或 Jetson Nano 这种 100 美元级的板子上跑, 更是门
都没有。这形成了一个很奇怪的局面: 2026 年了, 实体机器人
的"大脑"还只能在价格几万美元的设备上跑, 根本没有普适性。

**SomaOS 的设计思路**: Brain Next 的执行内核在设计时就内
置了一条**非功能性天花板约束**: 稳定运行所需资源不超过
**1GB 内存 + 4 核 ARM (Cortex-A72 级别)**。这是一个不是"最
低推荐配置"而是"设计目标约束"的强条件——任何新功能如果
会把内核推过这条线, 就会被要求重构或重写, 而不是升级推
荐配置。

这条约束带来两个连锁收益:
1. 即使在资源更宽裕的 Jetson Orin 上运行, 内核也只会占
   用系统资源的极少部分, **把绝大多数资源留给 VLA 推理和
   感知**, 这正是 VLA-Pluggable 设计 (§3) 想要的资源配比。
2. 它把机器人"大脑"的入门成本下探到了 100 美元级的单板
   计算机, 让 SO-100 这种消费级机械臂的用户, 真的可以在一
   台和树莓派相当的设备上拥有一个安全、可验证、可升级的
   运动大脑。

## 设计特征总览表

| 特征 | 公开描述 |
|---|---|
| **零依赖 (Zero-dependency)** | 运行时 `dependencies: {}`, 仅使用标准运行时内置模块; 供应
  链攻击面为零, 可审计可确定 |
| **双重动作筛选安全** | 慢路 (意图级四规则并行否决) + 快路 (反射级扭矩释放直通)
  代码调用数据三独立 |
| **极低资源需求** | 在 1GB 内存 + 4 核 ARM 级设备上稳定运行 |
| **VLA 热插拔** | 上游视觉-动作模型通过标准化契约热插拔; 换 VLA 不重做安全
  验证 |
| **高价值失败优先经验回放** | 三类高价值失败信号 (自信错判 / 新场景首败 / 安全误拦漏
  拦) 标注 + 过采样加权 + 单样本次数上限防过拟合 |
| **全链路事件可追溯** | 所有关键决策事件结构化落总线, 可诊断, 可用于训练数据制作 |
| **独立运行** | 不依赖任何其他大脑、不共享状态, 可单独装机运行 |

```
+--------------------------------------------------------------+

                            v
+==============================================================+  第一层 慢路 (意图级动作筛选)

                            v

|  Traceable Event Bus (全链路事件 + 诊断快照 + 高价值失败打标)|
+--------------------------------------------------------------+
```

## 能力声明 (公开对外的能力类型)

本大脑声明具备以下公开能力类型 (**仅声明能力域, 不承诺具体
对外接口协议与性能数值**):

- **视觉感知入口**: RGB 相机输入 (可直接接入或通过上游 VLA 处理)
- **语音指令入口**: 语音指令输入 (可直接接入或通过上游 ASR/VLA)
- **末端操作**: 6 自由度末端位姿控制 + 夹爪抓取 / 释放
- **智能扩展**: 外部 VLA 推理热插拔接入 + 高价值失败优先经验回放
- **安全保护**: 双层动作筛选 + 强制急停 + 扭矩立即释放 + 冷却限制
- **可诊断性**: 全链路结构事件 + 诊断快照回传

## 与 SomaOS Cognitive Brain (认知意识脑) 的关系

两个项目**互相独立**。每一个都具备完整的感知-理解-规划-执行
闭环, 各自可作为独立大脑单独装机运行。它们的关系是:

- **RCAN 抽象层命名一致性**: 两者对外使用同一套标准化指令语义。
- **硬件目标一致性**: 两者均面向 Feetech SO-100 机械臂做集成适配。
- **零交叉依赖**: 不共享代码库、不共享数据集、运行时状态互不接触。

这种关系恰好对应 2026 年业界验证有效的 **"Cerebrum (皮层 GPU)
— Brainstem/Cerebellum (脑干/小脑 ARM/MCU)"分工模型**。用户
可根据目标场景自由组合 (只装认知脑、只装运动脑、或在同机同
硬件目标上各自独立运行做双层决策)。
